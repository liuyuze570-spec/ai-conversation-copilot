## 2. 真实翻译（本地 Opus-MT，进程内 ONNX）

模型：`Xenova/opus-mt-en-zh` 量化 ONNX，encoder 52,899,742 字节 + decoder 60,212,804 字节，
合计 107MB。beam=4（模型自带 `num_beams`），长度惩罚 1.0，贪心可复现（同一输入两次同结果）。

| 英文原文 | 实际译文 | 耗时 |
|---|---|---|
| Please send the report by 3 p.m. tomorrow. | 请在明天下午3时前将报告发送。 | 615–876ms |
| The meeting is not on Tuesday. It has moved to Thursday at 10:30 a.m. | 会议不是在星期二举行,而是在上午10时30分改为星期四举行。 | 788–854ms |

| The train leaves at seven forty-five from platform two.（**新句，未预置**） | 列车从2号平台745出发 | 521–565ms |
| The delivery is not on Friday. It will arrive next Monday at 9 a.m.（**新句，未预置**） | 星期五不送货,下星期一上午9时到 | 594–722ms |

**模型加载**：845ms（首次），启动阶段预热一次，第一个用户不用等。
**并发**：单进程内串行（一把锁），同一时刻只跑一个翻译。

### 这一组里真实存在的问题

`seven forty-five` 被识别成 `745`，译文成了「745出发」——数字对，但**时间形式丢了**，
读者可能读成「七百四十五」。我给识别加了 `initial_prompt` 提示书写格式，
`9am → 9 a.m.` 修好了，`745` 没修好。不猜着改的原因是：`room 745` 同样会被改写错，
把「房间 745」改成「7:45」比不修更危险。**这一条列为已知缺陷**，界面上的对策是
原句始终显示、事实卡允许手工改值，不替用户下结论。

### 顺手修掉的一个真 bug

第一次测总开关时发现：`COPILOT_REAL_DISABLED=1` 下 `/api/health` 回报
`mode=mock / real=false`，但 `/api/translate` **仍然调了真实模型**，
返回 `mode=local-onnx`。原因是那处判断写成了 `if ... : pass`，什么也没做。

这种不一致比没有开关更危险：运维看到「已关闭」以为停了，费用和隐私承诺都在继续。
现在统一由 `backend_or_none()` 选路，三个接口（translate / transcribe / reply）
都强制只走 mock 那一路，未命中就明确报错。改动后重跑上表 3 行，行为一致。

## 11. 2026-11-09：匿名会话失效的定位与修复（0.7.0-web.3）

### 11.1 故障现象与影响面

公网实测记录（`outputs/公网估分检查/本次实测记录.json`）：未预置的英文提交后提示
「会话过期了，刷新页面会重新建立匿名会话」，刷新重试**仍然**失败；预置样例与
「改金额 → 确认句」闭环可以正常操作。

这一点很关键：它说明**模型没问题、静态资源没问题**，坏的是「页面与服务端之间那层匿名会话」。
我在 10:11 用同一条链接复现了一次（`/api/transcribe` 返回 `SESSION_REQUIRED`），
而 8 分钟前用同一个 Cookie 建会话、立刻翻译是 8/8 成功的 —— 说明不是稳定复现，
而是和「会话在哪台进程、请求被谁接走」有关。

### 11.2 定位过程（只记结论，不记 sid）

| 检查 | 结果 |
|---|---|
| `POST /api/session` 是否正常 | 200，`Set-Cookie: sid` 正常下发，`curl -c` 能存住 |
| 建完会话「立刻」翻译 | 连续 8 轮 **8/8 成功**，延迟 400–810ms |
| 同一 Cookie 隔几分钟再用 | 出现 `SESSION_REQUIRED` |
| 会话有效期 | `SESSION_TTL=7200s`，不是两小时过期 |
| 代码路径 | `require_session` 只读 Cookie；会话表在内存；`SESSION_REQUIRED` 一个码同时代表「没带 / 不认识 / 过期」 |

结论：会话是**进程内内存表**，页面手上的会话在以下任一情况下就变成「不认识」——
进程重启（部署、内存回收）、请求被另一个实例接走、Cookie 在代理或浏览器隐私设置下丢失。
旧实现把三种情况压成一句「会话过期，刷新页面」，而刷新只会再建一个新会话、再撞一次同样的问题，
用户就卡在「刷新也没用」。

### 11.3 修法（不关鉴权，不放宽配额）

后端（`webapp/server/app.py`）：

1. 会话标识支持两条通道：HttpOnly Cookie（主）+ `X-Session-Id` 请求头（备）。
   两条都查**同一张会话表**，没有新增任何免鉴权路径。
2. `SESSION_REQUIRED` 现在带 `reason`（`missing` / `unknown` / `expired`）和 `recoverable: true`，
   排查时能分清是「没带」还是「不认识」。
3. 会话检查在扣配额和跑模型**之前**（`require_session` → `spend` → 模型），
   所以「重建会话再重试」不会重复计费。
4. `/api/health` 增 `diag`：`boot`（每进程一个短 ID）、`uptime_s`、`sessions`、`session_transport`。
   不含 sid、密钥、正文。有了 `boot` 才能判断「请求是不是换了进程」。
5. 版本号 `0.7.0-web.1` → `0.7.0-web.3`，构建标识 `web3-2026-11-09`，可直接在 health 里核对。

前端（`webapp/web/src/api.ts`、`state.ts`、`App.tsx`）：

6. 会话就绪前，真实调用按钮**不可提交**（`sessionState` 三态），并显示「正在建立匿名会话」；
   健康徽标不再被当成「可以用了」的依据。
7. `withSession()`：先确保会话 → 发请求 → 只在 `SESSION_REQUIRED && recoverable` 时
   重建**一次**并重试**一次**；其它错误原样抛出，绝不悄悄重发（重发等于让用户为同一句话付两次额度）。
8. 失败时保留输入，给出「重试一次」入口；不再让用户猜「刷新一下试试」。

## 13. 2026-11-09：翻译质量与多语言（0.7.0-web.6）

### 13.1 用户报的那个现象，复现出来是这样的

用户截图：输入 `hellow`，译文「地狱」，读音「希洛乌」。三样全错。

本地直接调引擎复现（`webapp/server/engine_mt_onnx.py`，量化权重 107MB）：

| 输入 | 修复前输出 | 问题 |
|---|---|---|
| `hellow` | `地狱` | 拼写变体被切成 hell + ow |
| `hello` | `哈哈哈哈哈哈哈哈哈` | 解码重复退化 |
| `Good morning` | `早早早早早` | 同上 |
| `hi` | `hi hi hi` | 原文原样吐回，没翻译 |
| `thank you` | `感谢您,感谢您` | 整句重复两遍 |

三类原因叠在一起：

1. **短输入下解码退化。** 没有上下文的两个词，beam search 会挑「每步概率都不低」的
   重复路径。`max_length` 又固定给 512，于是可以一路重复到 EOS。
2. **拼写变体没有兜底。** `hellow` 不在词表里，分词器切成 `hell` + `ow`，
   `hell` 译成「地狱」。
3. **读音只按字母拼。** `hellow` 走到规则拼读，得到「希洛乌」——不是近似，是另一个词。

### 13.2 改了什么

**服务端**

- `phrasebook.py`（新增）：人工整理的常用语表 **391 句 + 248 词 + 75 条拼写修正**，
  以及日/韩/俄各约 30 句问候。命中即直出，`mode="phrasebook"`，界面标
  「常用语库 · 人工整理，不是模型」。**拼写变体只用于查表，不改写用户原文。**
- `engine_mt_onnx.py`：加 `no_repeat_ngram_size=3`；输出长度按输入自适应
  （`min(512, max(24, enc_len*4.5+12))`）；修 beam 提前结束时的 batch 形状错位
  （原来某个 beam 结束后 `hidden` 仍是 4 行、`seq` 少一行，会直接抛异常）。
- 退化自检 `looks_degenerate()`：空译、原样吐回、单字连续重复 ≥4、同词重复 ≥3、
  长度失控，五类判为退化。命中时**跳过这一路**继续试下一路；全不行返回
  `TRANSLATE_FAILED`（422），不把「哈哈哈哈」当成功展示。

**前端**

- `modeLabel` 增加 `phrasebook` 与 `local-cascade` 两种来源；
- 手误命中时显示「你打的是一个常见手误，这条按「hello」查的；上面的原文没有改动」；
- 单词命中时显示「这是这个单词的常用词义，不是整句翻译」；
- 常见语库直出时，状态栏写「常用语库直接命中 · 没有调用模型」，
  不再显示「翻译完成 · 0.00s」（那会让人以为模型瞬间翻完）；
- 读音表补 `hellow/helo/hii/thx/pls/...` 等变体，与后端 `SPELL_FIX` 同源。

### 13.3 多语言：日/韩/俄

没有「→中文」的现成 ONNX 量化模型（`Xenova/opus-mt-{ja,ko,ru}-zh` 均 404），
自己转 ONNX 要拉 optimum + torch（GB 级），所以走**两级**：

```
日语/韩语/俄语 --(opus-mt-xx-en)--> 英语 --(opus-mt-en-zh)--> 中文
```

模型来自 hf-mirror（`Xenova/opus-mt-ja-en`、`-ko-en`、`-ru-en`，各约 110MB，
量化权重 + tokenizer）。下载脚本 `fetch_models.py` 记了仓库与许可；
`fetch_models.sh` 是直链版本（`api/resolve-cache` 会超时，`/resolve/main/` 能连）。

实测（本地 8899，真实请求）：

| 输入 | 中文 | 中间英语 | 耗时 |
|---|---|---|---|
| 明日の会議は何時ですか | 明天的会议几点了? | What time's tomorrow's meeting? | 2.2s |
| 会議は火曜日ではありません。木曜日の10時30分に変更されました。 | 会议不是星期二 改成星期四10点半 | The meeting isn't Tuesday. It was changed to 10:30 Thursday. | 2.5s |
| 내일 오후 3시까지 보고서를 보내 주세요. | 明天下午三点前把报告寄给我 | Send me your report by 3:00 tomorrow afternoon. | 2.4s |
| Пожалуйста, пришлите отчёт завтра до 15:00. | 请在明天下午3:00前提交报告。 | Please send a report by 15:00 tomorrow. | 2.0s |

**代价写在界面上**：`local-cascade` 会显示「日语这一版没有直译中文的模型，这句是
「日语 → 英语 → 中文」两级转译，措辞可能比英译中粗糙」，并把中间那句英语一并显示。

### 13.5 自动回复

### 13.9 上线之后又抓到一处：句尾复述

这一条是**发布之后**在线上复验时发现的，不是用户报的，记在这里因为它是确定性的、
谁都会遇到：

| 输入 | 上一版译文 | 现在 |
| --- | --- | --- |
| `We will meet you at three o'clock` | 三点见**,三点** | 三点见 |
| `See you tomorrow` | 明天见**,明天** | 明天见 |
| `Ждём вас в три часа`（→ 英语 → 中文） | 三点见**,三** | 三点见 |

原因：模型在句尾把刚说过的半句又复述了一遍。它**不是**同词重复（逗号两侧不是同一个
词），所以 `no_repeat_ngram_size=3` 在解码阶段抓不到 —— 复述发生在字符层面，只能在
出来之后处理。

修法 `phrasebook.drop_repeated_tail()`：只看**最后一段**，且它必须完整出现在前面的
内容里，长度不超过前半的一半，才判定为残句。判据故意收得很窄，因为**砍掉用户本来
就说的话，比多留一个残句危险得多**。反例都进了测试：

- `我们三点见,三点之前到` —— 不动（尾段前面没有）
- `你好,谢谢` —— 不动（尾段不在前文）
- `一,二,三` —— 不动

回归测试：`webapp/server/test_phrasebook.py`，**8 条**（查表 5 + 退化自检 2 组 + 修剪 2 组）；
与 `test_mt_onnx`（5 条）一起跑 **13 条全过**。本地端到端 8 步（`webapp/e2e/run.mjs`，
`WEB_BASE=http://127.0.0.1:8899`）**FAILED_STEPS `[]`**、console 错误 0。

**没有变的**：13.7 那三条整句事实错误（凭空币种、丢否定、「改到」读错）依旧存在，

### 14.2 实现要点（为什么这几句能对上）

- **币种只看原话**：`currencyOf(originalText)`；原话没提，事实卡写「币种没说是**原话没说**，不是默认美元」。
- **译文修正只减不增**：`phrasebook.strip_invented_currency`（剪模型补的币种）、`express_reschedule`（把丢掉的「改到」补回），改动都在响应 `corrections[]` 里点名，界面黄条说明，不悄悄替换。
- **改期是三张卡**：`role` = origin / current / duration；旧安排**不进**确认句。
- **合并配对先对齐否定与角色**：中文日期抽取顺序跟出现顺序无关，盲配会把「周四上午」配上 Tuesday、否定标记跟着串过去（周四被划掉、周二成了当前安排）——实测抓到并已修。
- **裸数字金额按字符区间排时间**：`2 p.m.` 的 2 不再漏成「金额 2」。
- **回复卡本地生成**：`reply-plan.ts` 按事实拼（不调模型、不依赖网络），翻译成功即出；英文句只用对方自己的词（`labelEn`），中文类名（「金额」）只进中文句——浏览器实测抓到过「the 金额 is 300」并已修。
- **第三张兜底**：「请对方打字」（Sorry, could you type that instead?）——对听障用户最实用且不暴露听力状况。

**根因与修法**：

- **① 中文展示值被拼进英文句**：双语事实合并后 `value` 是给中文用户看的「450欧元」，
  `sourceText` 才是原话「450 euros」。旧 `moneyClause` 直接用 `value`。现在
  `englishAmount()` 把**数字 / 币种 / 中文展示值**三路分开：数字从原话片段抽，
  币种走 `currency` 代码 → 英语口语词（EUR→euros），原话本来是英文就照抄，
  推不出数字宁可让确认句不成立也不编。`englishFragment()` 同样挡住时长里混进中文。
- **② 纯数字被字母规则吃光**：`enTransliterateWord` 把 "300" 清成空串，整句 join 时
  悄悄略过。`pronunciation.ts` 新增数字英语读法：`integerWords`（450 = four hundred fifty）、
  `clockWords`（4:20 = four twenty，4:05 = four oh five）、`decimalWords`（12.5 =
  twelve point five）、千分位与 `$` 前缀；句尾标点先剥掉（`900.` 也读得出）。
  数词 → 汉字近音表；推不出时返回 `〔数字读音未确定〕` **显式占位，不返回空串**。
  另加 `missingNumberHints(en, phon)`：界面拿它做第二道防线，缺哪个数字就点名哪个，
  并写「请照英文正文念，不要跳过」。
- **③ 焦点锚点只挂在唯一一颗按钮上**：`cardTrigger` 原来作为 `ref` 绑在确认句
  「放大给对方看」上，回复卡三颗放大按钮打开时它是 null。改成**打开时记
  `event.currentTarget`**（`openBigCard`），弹层卸载统一由 `restoreFocus` 归还；
  触发元素已被卸载（`document.contains` 为假）时退到 `h1[data-focus-fallback]`。

**核心回归没有倒退**：金额 / 币种 / 否定 / 改期 / 时长仍在 `.dev/p0-fidelity-unit.mjs`
35 条与 `p0-verify` 的 A/B/C 组里，原话无币种仍显示「币种未说明」、周四仍划掉标

### 18.1 问题①：为什么回复总是那三句，改了什么

真实原因：`src/shared/reply-plan.ts` 只有在抽到金额 / 日期 / 时间 / 否定 / 改期事实时才换句子；
影视对白、寒暄、叙述**没有这些事实**，于是每次都落到三条写死的兜底句
（`Sorry, could you say that again a little slower?` / `Thank you, I've got it.` /
`Sorry, could you type that instead? It is easier for me.`）。截图里正好是这三句，用户抱怨属实。

修复（全部是本地规则，不冒充模型）：

- 新增 `detectScene()`，按句式与关键词分 10 类：问候 / 道谢 / 道歉 / 提问 / 道别 /
  邀请 / 最高级强调 / 观点 / 叙事 / 普通陈述；实测发现 `Hi there, good to see you.` 里的
  `see you` 会被道别规则误抓，已把问候规则前移。
- 新增 `contentReplies()`，每个场景给「内容回应 + 内容追问」两条，第三张保留
  「请求重复 / 放慢 / 打字」这条底线。所有英文句都不替用户承诺、不暴露听力状况、不夹中文。
- `ReplyPlanInput` 增加 `context`（累积前文）；短句 `Yeah.` / `Right.` 借上一句判场景，
  不会在连续对白里一次次落回同一句。卡片 `why` 会写「已结合前面 N 句」。
- **有事实的句子完全不进新分支**：金额、币种、否定、改期、时长的确认句保持原样，
  P0 回归 35 + 52 条与浏览器断言全部不倒退。

真 AI 的边界（界面明说，不糊弄）：`/api/reply` 的 `ProviderReply`（云端模型）本来就存在，
但 `COPILOT_LLM_BASE_URL / COPILOT_LLM_API_KEY / COPILOT_LLM_MODEL` **均未配置**，

### 18.2 问题②：两条轨道

| 轨道 | 行为 |
| --- | --- |
| ① 逐句字幕 | **保持原样**：一条一条出，编号、识别/翻译模式、延迟、半句标记、逐句译文都不变 |
| ② 整段连贯翻译 | 把到目前为止**全部**成句原文合起来，按句子边界分块（500 字/块、最多 4 块），逐块走真实 ONNX 翻译后拼成一段；超过块数上限如实报 `omitted`，不静默丢内容 |

交互按用户描述实现：

- 「**暂停并整段翻译**」：停止切片与排队但**保留音频轨**，自动对全部累积内容整段翻译。
- 「**继续采集**」：不用再选标签页，继续累积；暂停期间 worklet 推来的数据直接丢弃，
  不会把停掉那段一起识别出来。新句子进来后整段译文立刻标 `stale`，界面写明
  「它是暂停/停止那一刻的快照，不是实时译文」。
- 「**停止并释放**」：释放全部轨道，同时**自动再整段翻译一次**（`trigger=stop`）。
- 「刷新整段翻译」：手动重翻（`trigger=manual`）。
- 「用全部内容生成回复」：把整段原文、整段译文和全量上下文送进主流程，
