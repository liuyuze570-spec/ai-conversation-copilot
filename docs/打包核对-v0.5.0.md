## 二、包内是否含数据库运行依赖（本轮重点）

`app.asar` 共 228 个条目，其中：

```
\node_modules\node-sqlite3-wasm
\node_modules\node-sqlite3-wasm\LICENSE
\node_modules\node-sqlite3-wasm\dist
\node_modules\node-sqlite3-wasm\dist\node-sqlite3-wasm.js
\node_modules\node-sqlite3-wasm\dist\node-sqlite3-wasm.wasm     ← 1.29 MB，纯 WASM，不需要本机编译
\node_modules\node-sqlite3-wasm\package.json
```

- 这是**纯 WASM** 构建，没有 `.node` 原生模块，用户机器不需要装 Python / VS 构建工具；
- `.wasm` 被打进 asar，Electron 的 asar 补丁让 `fs.readFileSync` 能直接读；
- `dist\main\history-db.js` 里确实 `require('node-sqlite3-wasm')`，且含 `user_version` 迁移逻辑。

## 三、界面产物是否是最新构建（字节比对，不用 grep）

grep 压缩后的函数名不算证据 —— 这里直接比字节：

| 文件 | asar 内大小 | 与 `dist/renderer/assets/` 逐字节相同 |
| --- | --- | --- |
| `index-Dzs1col3.js` | 350 217 | **是** |
| `index-CLqPwz-J.css` | 30 955 | **是** |

`dist/renderer/index.html` 引用的正是这两个文件名，没有指向旧 hash。

## 四、在打包版上跑同一份界面自检（最强证据）

```
release\win-unpacked\"AI Conversation Copilot.exe" --user-data-dir=<独立目录>
    （环境变量 COPILOT_V050=<输出目录>）
```

结果：**17 个步骤全部产出，退出码 0**，报告另存
`docs/evidence-v0.5.0/selfcheck-report-packaged.json`。关键项：

| 项 | 打包版实测 |
| --- | --- |
| 数据库打开 | `ready: true`、`integrity: "ok"` |
| 库文件位置 | 指向传入的 `--user-data-dir`（说明确实读的是 `app.getPath('userData')`） |
| 写入回执 | `save-state = "saved"` |
| 读到内容 | 1 会话 / 1 条；原文、译文、谐音与界面一致 |
| 记录面板 | 「共 1 段 · 1 条消息 · 40 KB」，详情 1 条 |
| 关掉重开（重载窗口） | 空状态显示「上次的记录还在」，点开逐字段一致 |
| 高对比 | 纯黑底 + 纯白字，读渲染色算 **21:1** |
| 字号 | 调译文 / 调谐音互不影响，重载后仍保持 |
| 历史详情字号 | 详情里三行 `18px / 32px / 24px`，与当时的设置逐项相等 |

**结论**：安装包本身跑得起来，数据库依赖进包且可用。这一条是"未装开发环境的
Windows 也能运行"的直接证据（同一台机器上脱离源码目录运行解包版）。

## 五、包里**没有**什么（逐项核对）

| 检查 | 结果 |
| --- | --- |
| 用户真实记录库 `history.db` | 不在包内（打包只含 `dist/**` + `package.json` + python 运行时 + docs） |
| `.backup/` 里的历史配置备份 | 不在包内 |
| `.dev/` 开发脚本与临时输出 | 不在包内 |
| `logs/app.log`、调试日志 | 不在包内 |
| 真实 API Key | 不在包内（Key 只存在用户机器 `%APPDATA%`，且 DPAPI 加密） |
| 用户录音 / 视频 | 不存在（产品本身不保存音频） |
| 源码 `.ts` | 不在包内（只有编译后的 `dist/main/*.js`） |
