## 第 1 页 · 问题：卡住的地方不是「听不见」，是「说不出口、不敢确认」

**一句话**：听障者戴着助听设备能听见声音，但在英语会议里，他卡住的地方往往是
**没法开口**和**不敢确认自己听对了没有**。

三个卡点（**按使用场景挑的，不是统计出来的频率排序**）：

1. **请对方再说一遍** —— 说不出口，只能点头。
2. **改期** ——「会议不是周二，是周四上午 10 点半」，听到的是周二，不敢确认。
3. **金额** ——「一万五，不是五万」，两个数字都在耳朵里，签字前才发现记反了。

现有工具解决的是「把话变成字」。我们的判断是：光有字幕不够，还得能
（a）看懂、（b）念出来、（c）把关键数字确认下来。

**所以做的是一条链**：系统声音 → 外语原文 + 你看得懂的译文 → 与原句一一对应的读音提示
→ 一句能直接说出去的回复 → 关键事实的确认记录。

> 状态：`已实现`（链路各段都有自动化测试）+ `预置模拟`（演示模式下不接真实音频）

## 第 2 页 · 做法：确认卡不是「显示信息」，是「保证你说出口的和你想的一样」

这一版最重要的一条修复，恰好说明为什么确认卡是核心创新而不是装饰。

**实测到的 bug**：用户把「当前理解」从 15,000 改成 16,000 之后，确认卡生成的
英文句子仍然是 `15,000 dollars`，中文释义却是 `16000美元`。他照着英文念，
对方听到的仍是旧数字 —— **确认卡在帮他确认一个错的值**。

**修法（v0.6.2）**：确认句不再「一半用原话、一半用改后的值」，而是两边都从**当前理解**出发：

1. 能机械推导的（时间点、星期、金额数字）在原话结构上替换：
   `10:30 → 11:30`、`Thursday → Friday`、`15,000 → 16,000`，连上下午、千分位写法一起保留。
2. 推不出来的（换币种、换地点、改成「还没定」）**拒绝生成**，提示「点改说法，用外语写一句」，
   由用户补 —— **不给半截句子**。
3. 模型那条路也过同一道闸：句子里必须出现改后的值、不许出现改前的值、释义必须同源。
4. 改过的事实自动回到「待确认」，旧确认时间作废，上一条确认句作废。

**四个设置互相独立，且不按国籍推断语言**：

| 设置 | 取值 |
| --- | --- |
| 界面语言 | 简体中文（本版固定） |
| 你理解的语言 | 中文 / 日本語 / English |
| 我想说的语言 | 英语 / 日语 |
| 读音提示体系 | 汉字近音 / 片假名 / 罗马字 / 关闭 |

**实测覆盖的三个方向**：中文 → 英语、日本語 → 英語、English → 日本語。
其余组合可以在设置里选，但界面写明「不在实测清单内」，**不说「支持全球所有语言」**。

读音提示按词与原文对齐，来源分四类并在界面上分开标：
**词典命中 / 规则近似 / 我的读法 / 未确定**。
「词典命中」不等于母语者核对过，「我的读法」也不标成专家核对 ——
**本版没有任何真实核对记录，所以界面不出现「人工核对」这个状态。**

> 状态：`已实现` + `未验证`（读音没有母语者核对，见《读音核对清单-v0.6.1》）

## 第 3 页 · 现场演示：三条样例 + 一次现场改值（8 分钟）

演示环境：本机、演示模式（不碰声卡、不调用付费接口），三组**预置**样例。
**演示模式全程有橙色横幅写明「听不到电脑里的声音」**，不让人误以为在跑真实识别。

| # | 场景 | 台上做什么 | 观众看到什么 |
| --- | --- | --- | --- |
| 1 | 请再说一遍 | 点「我没听清」 | 一句能直接念的英语 + 逐词读音提示 |
| 2 | 不是周二，改成周四 10:30 | 看字幕 → 打开重点信息 → 勾「周四」「10:30」→ 生成确认句 | 「我理解的是周四上午 10:30，对吗？」；**周二显示为「被否定」，不是并列两个日期** |
| 3 | 一万五，不是五万 | 同上，勾金额 | 确认句里只有一万五；五万留在「被否定」那一行 |
| 4 | **现场把 10:30 改成 11:30** | 点「修改」→ 输入 11:30 → 回车 → 重新生成 | 英文句子变成 `11:30 a.m.`，中文释义同步变成 11:30；这一行从「已确认」回到「待确认」 |

第 4 条是这一版专门加的动作，因为它能当场证明「确认卡说的是你现在的理解，不是原话」。
再往下改一个推不出说法的值（例如把日期改成「还没定」），会看到「需补说法」而不是半截句子。

中间穿插两个 15 秒的动作：

- **点词**：点字幕里的 `Thursday`，提示行对应那段同时亮 —— 证明提示和原句一一对应。
- **翻卡片**：把屏幕转向评委，30px 大字；翻回来是自己的释义面。

**台上不说的话**：

- 不说「支持所有语言」。
- 不说「谐音/发音准确」。
- 不说「任何会议软件都支持」—— 只验证了抓系统默认输出这一条路径。
- 不说「已实现离线识别或离线翻译」—— 断网时能给的是**已有字幕可查、沟通卡、文字输入、
  已有回复、本地朗读**，不是新的识别结果。

> 状态：`预置模拟`（三条样例的译文）+ `已实现`（交互、确认卡、改值重算）

**AI 工具怎么用的**

- 用来写代码骨架、查 API、生成测试结构；**每条结论都回到代码和真实运行里核**。

  因为用例只覆盖平假名。这是补片假名、未知汉字、缩写用例的直接原因。

  实际版本对不上；**版本只认字节，不认记忆**。本轮重新核实：B 盘是 0.6.1，不是 0.6.2。

**下一步（按优先级）**

1. 补真实链路：换有余额的账号 + 装英语语音包，跑完整「说话 → 字幕 → 回复 → 朗读」。
2. 用它跑一次真实模型确认句，检查模型的句子能不能过那道闸（现在是代码写好、未实测）。
3. 找 1–3 位听障使用者做 30 分钟任务测试（任务脚本已写好，等人）。

5. 回复流式化；Electron 从 33 升级。

**已知不足，主动说明**

- 记录用 `delete` 回滚日志而不是 WAL（这个 WASM 构建下 WAL 不生效），写入比原生慢，
  但同样原子；容量边界写在《数据存储与备份-v0.6.2》里，**不承诺无限容量**。

1. 旧文件里的「Python 作为主要实现语言」是否仍然适用 —— 我们只用 Python 做 WASAPI 采集 sidecar。
