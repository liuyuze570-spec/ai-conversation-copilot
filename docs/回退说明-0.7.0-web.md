## 2. 版本与构建的对应关系

网页版是单端口 Python 服务（`webapp/server/app.py` + `run.py`），前端产物放在
`F:/copilot-deploy/app/web/app`。发布平台会排除 `dist/`，所以部署副本必须用
`web/app` 这个名字。

版本号写在两处，发布前**必须先改**，否则 `/api/health` 报的还是旧版本，
事后无法判断到底有没有发布成功（这个错在 web.6 发布时踩过一次）：

```
webapp/server/app.py:46   VERSION = "0.7.0-web.X"
webapp/server/app.py:47   BUILD_ID = os.getenv("COPILOT_BUILD_ID", "webX-YYYY-MM-DD")
```

改完要同步到部署副本：`cp webapp/server/app.py F:/copilot-deploy/app/server/app.py`。

## 3. 回退步骤（预案，未演练）

### 3.1 从标签取回稳定版源码

不要 `git reset --hard`，也不要动当前工作区的增量提交。用独立的 worktree：

```bash
cd "F:/3D打印Rhino 7.0/2026-09-30-23-01-15"
git worktree add "F:/copilot-rollback-web7" stable-web.7
```

### 3.2 重建 web.7 前端

```bash
cd "F:/copilot-rollback-web7/webapp/web" && npm ci && npm run build
```

（web.7 的 `src/shared` / `src/services` 也在同一 worktree 里，Vite 的 `@shared`、
`@services` 别名会指到该 worktree 的版本，不会混进 web.8 的代码。）

### 3.3 覆盖部署副本

```bash
rm -rf "F:/copilot-deploy/app/web/app"
mkdir -p "F:/copilot-deploy/app/web/app"
cp -r "F:/copilot-rollback-web7/webapp/web/dist/index.html" \
      "F:/copilot-rollback-web7/webapp/web/dist/assets" \
      "F:/copilot-deploy/app/web/app/"
cp "F:/copilot-rollback-web7/webapp/server/"*.py "F:/copilot-deploy/app/server/"
```

`web.7` 没有 `feedback_store.py`，但 `app.py` 也不会 import 它；多留一个文件不影响启动。
**不要删 `F:/copilot-deploy/app/server/data/feedback.sqlite3`**：那是用户反馈数据，
回退代码不该连带删数据。回退后 web.7 没有反馈接口，数据只是暂时查不到，恢复 web.8
之后仍可按原编号和凭证查询。

### 3.4 发布（必须显式带启动命令）

```
workbuddy_sites_deploy:
  directory   = "F:/copilot-deploy/app"
  language    = "python"
  startCmd    = "python run.py"     ← 不传会跑 main.py，报 SITES_START_FAILED，链接会短暂打不开
  domainPrefix= "en-zh-caption-helper"
  appName     = "跨语言沟通助手"
  userAskedToPublish = true         ← 需要用户在这一步明确同意覆盖线上
```

### 3.5 验证回退成功

curl -s --noproxy '*' "https://en-zh-caption-helper.app.workbuddy.host/api/health?sharecode=X3A6YY6GQH" \
