## 2. 可复现演示 A：真实音频链路（本轮已跑通）

**音频来源**：`webapp/server/testdata/s1-report.wav`、`s4-new.wav`、`s2-meeting.wav`。
这三段是 `make_test_audio.py` 用 **Windows SAPI5 合成的英语句子**，不是真人录音，
更不是视频网站原声。合成时的语音名、语速记在 `testdata/meta.json` 的设计说明里。
用途只有一个：验证切片 → 识别 → 断句 → 翻译这条链路真的会动，且能测出延迟。

**步骤**

1. 打开 `http://127.0.0.1:8901`，进「字幕」页，滚到「翻译其他网页视频」。
2. 打开 Chrome DevTools Console，执行（`docs` 里的 E2E 脚本 `webapp/e2e/p2-verify.mjs`
   会自动完成这一步）：

   ```js
   // 把三段 WAV 解码拼成一条真实 MediaStream，再注入自检入口
   const files = ['s1-report.wav','s4-new.wav','s2-meeting.wav'];
   // 见 p2-verify.mjs 的 page.evaluate：atob → decodeAudioData →
   // createBuffer → createBufferSource → createMediaStreamDestination
   await window.__COPILOT_TAB_AUDIO_TEST__.inject(destination.stream);
   ```

3. 观察状态从「采集中」变成「等待声音」，字幕按编号出现；点「停止并释放」。

**注入口只接真实音频 MediaStream，不产生任何文字。** 界面会把音源如实标成
「自检音频（本地合成语音，不是视频原声）」，绝不会写成「视频标签页」。

一键复跑（真 Chrome）：

```bash
node webapp/e2e/p2-verify.mjs          # 默认 8901；可用 WEB_BASE 覆盖
```

### 2.2 识别误差：照实写，不许美化

| # | 识别原文 | 中文译文 | 评价 |
| --- | --- | --- | --- |
| 1 | Please send the report by 3 p.m. tomorrow. | 请在明天下午3时前将报告发送。 | 正确 |
| 3 | I will bring the blue folder to the office at 4.50 p.m. 13 p.m. on Friday. | 我将于星期五下午4时50分13时将蓝文件夹带回办公室。 | **错**：原句 4:15 / 10:30 a.m.，且多出 `13 p.m.` |
| 4 | The meeting is not- Not on Tuesday. | 周二不开会, | **错**：重复词，后半句丢失 |

根因：固定 3 秒硬切片会切在句子中间，faster-whisper base 对半句容易补错数字与重复。
**这一版解决的是「链路跑通」，没有解决「识别准确率」。** 这三条字幕不能用于宣称
「翻译正确」，也不能用于评价听障使用者实际能不能看懂。

下一步应做 VAD 端点检测 / 带重叠的滑窗 + 句级合并，再用同一套合成语音与真人录音
分别复测；不是把切片时间调长硬凑一句。

   视频声音照常从原标签页播放；字幕在助手窗口里按编号出现（并排看）。
5. 点「停止并释放」，确认状态「已停止，所有采集轨道已释放」。

- 视频标签页关闭 / 停止共享 → 音轨 `ended`，自动停止并提示。

### 4.1 web.10 双轨增量（已发布到公网）

用户反馈「影视只能一条一条地回复，太慢，最好分两条，一条一条的不变，
另一条根据所有内容进行翻译，用户停止自动翻译，用户继续继续执行」。
web.10 在 P2 面板加了第二条轨道：

| 轨道 | 内容 |
| --- | --- |
| ① 逐句字幕 | 保持原样：一条一条出，编号、模式、延迟、半句标记、逐句译文都不变 |
| ② 整段连贯翻译 | 累积全部成句原文，按句分块（500 字/块、最多 4 块）后逐块走真实 ONNX 翻译再拼接 |

按钮与语义：「暂停并整段翻译」停切片但**保留音轨**并自动整段翻译；「继续采集」
不用重新选标签页，继续累积，整段译文立刻标「已过期 · 快照不是实时译文」；
「停止并释放」也会自动整段翻译一次；另有「刷新整段翻译」和「用全部内容生成回复」。

真 Chrome 实测（`p3-verify.mjs` 55 项 0 失败）：暂停 → `trigger=pause`、
1 块 `local-onnx`、1149ms、覆盖 2/2 句；继续并播放新音频 → 3 句、覆盖 2、
`stale=true`；手动刷新 → 覆盖 3/3、`stale=false`；停止 → `trigger=stop`、轨道全 `ended`。
完整数字与识别误差见测试报告第 18 节；截图 `docs/evidence-web/p3-dual-track.png`。

**限制**：整段译文是「分块翻译后拼接」，不是跨句改写或摘要；识别误差照样带进来。
web.10 已发布，公网也是双轨；线上 P3 首跑 51/55 的 4 项是验收脚本竞态误报，

## 5. 数据处理与隐私

- 用户主动点按钮、主动选标签页，才调用 `getDisplayMedia`；没有后台自动捕获。
- 只读取流里的**音频轨**。Chrome 要求同时请求 video 才允许共享标签页音频，
  所以会拿到一条 video 轨，但它只用来维持捕获会话，**不接元素、不取帧、不上传**；
  停止时一起 stop。
- 音频在本机切成 3 秒、16kHz 单声道 PCM WAV，按编号串行送 `/api/transcribe`；
  服务端日志只记 `seq / bytes / seconds / ms / 模式 / 错误码`，**不记正文**。
- 识别在本服务端完成（本机 faster-whisper，或服务端环境变量配置的识别接口），
  不把画面、整段录音或历史对话传给第三方。
- 不把捕获声音回放到扬声器：worklet 输出接 `gain=0` 的静音增益，
  避免助手自己的朗读被再次识别成循环。
- 停止会 abort 在途请求、清空排队、停掉全部轨道、关闭 AudioContext、撤销 worklet URL。
