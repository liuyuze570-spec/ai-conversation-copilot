## 1. 实际修改的功能和解决的问题

| # | 问题（真实发生的） | 改了什么 | 怎么证明 |
| --- | --- | --- | --- |
| 1 | 演示模式下，理解语言选中文 / 日语 / 英语，`Please send the report by 3 p.m. tomorrow.` 都返回「明天 / 下周」 | 演示翻译器之前**根本没读**「译成哪种语言」这个参数，长句还按关键词拼接。现在三句样例各有 zh-en / ja-en / en-ja 三个版本，按「理解语言 + 原话」查表；查不到就明说「没有这句的日语译文，不拿中文顶替」 | `samples-unit` 76 条（三方向 × 三样例译文逐字比对） |
| 2 | 保存失败后重试，**AI 回复永久丢失** | 之前数据库还没确认成功，就把「待写回复」清空、把缓存标成已保存。现在只有拿到成功回执才清；失败保留完整批次（含回复），自动/手动重试都会补 | `history-unit` + `samples-unit` S7（9 条） |
| 3 | 「用户明确清空」被旧值复活 | 空值一律当「没提供」处理，分不清删空。现在 `cleared` 白名单：没声明清空的不覆盖，声明清空的 upsert 后补 `UPDATE` 真置空 | K21–K24（含重开库后仍成立） |
| 4 | 现场麦克风收到的对方话被记成「系统声音」 | 按实际采集通道记 `mic` / `system` | 自检记录落盘项 |
| 5 | `PDF` 读成「普德夫」、`QR` 读成「克尔」、`p.m.` 读成「普姆」、`Mr.` 读成「姆尔」 | 缩写按**字母名**念、称谓查表；`PDF` → `匹 迪 艾夫`、`p.m.` → `皮艾姆`、`Mr.` → `米斯特` | `hint-unit` I 组 10 条 |
| 6 | 词典外的人名（`Okafor`）和词典命中的词，界面上长得一模一样 | 新增 `approx`（规则近似）状态，界面显示「规则近似 N 段」，用虚点线 + 文字，不只靠颜色 | `hint-unit` I 组 + 界面 |
| 7 | 会议/日程高频词靠字母硬拼（`report` → 瑞波尔特、`Monday` → 莫恩达伊） | 补词表：星期、月份、`meeting / budget / dollars / available / deadline / delivery / move` 与短功能词 | `hint-unit` J 组；10 句清单重跑 |
| 8 | 日语 `送ってください` 整句「部分未确定」 | 词典补 `送`（`おく`），`送 + って` 能读了 | 10 句清单 J01 现在整句 `ok` |
| 9 | 确认卡把「改到周四」的周四也标成已更正 | 按**值**判否定，而不是看整句有没有「改成」 | `competition-unit` H 组 |
| 10 | 旧文档写「B 盘安装版是 0.4.0」 | 读 asar 内 `package.json`，实际 **0.6.0**；两处文档已改正并留更正说明 | 见第 3 节 |
| 11 | 修完缩写之后，**打包版界面里** `p.m.` 还是「普 姆」 | Chromium 的分词器把 `p.m.` 切成 `p` + `m`（Node 切成一段），两次都落到规则拼读。现在「字母 + 点 + 字母」先合回一段再查表，单个字母也按字母名念 | 打包版自检输出 `3 普 姆` → `3 皮艾姆` |

## 6. 三组可体验样例（现场照着点就行）

打开软件 → 顶部确认处于**演示模式**（有橙色横幅「演示模式：听不到电脑里的声音」）。
理解语言 = 中文，目标语言 = 英语。三条都在样例面板里，点一条就能看到字幕 + 译文 + 提示 + 回复。

| # | 原话 | 应该看到什么 |
| --- | --- | --- |
| 1 | `Please send the report by 3 p.m. tomorrow.` | 译文「请在明天下午三点前把报告发过来。」；提示整句为词表命中（`p.m` → `皮艾姆`） |
| 2 | `The meeting is not on Tuesday. It has moved to Thursday at 10:30 a.m.` | 重点信息里**周二显示为「被否定」**、周四「待核对」；可生成「我理解的是周四上午 10:30，对吗？」 |
| 3 | `The budget is 15,000 dollars, not 50,000.` | 15000 为有效值、50000 为被否定；确认句里只有 15000 |

**顺手验两件事**（评委最爱看的）：

- 把「你理解的语言」从中文切到日语，再切回来 —— 三条样例的**译文和释义跟着变**。
  这是修掉的那个 bug，切了不变就是没修好。
- 点字幕里的 `Thursday` —— 下面提示行对应的那段同时亮起来，证明「提示和原句一一对应」。

另外提供一个更省事的读数方式：`node .dev/reading-list.mjs` 会把 10 句常用表达的真实提示
逐段打出来（不判断对错，只导出程序此刻会显示什么）。

## 9. 需要向主办方确认的问题（我没有自行宣称）

旧版技术说明和补充指南里关于下面两项的适用范围，我看到两种理解，**不敢替你定**：

1. **Python 的定位**：本项目用 Python 做 WASAPI 回环采集的 sidecar（音频采集这一件事），
   主程序是 Electron/TypeScript。如果比赛要求「必须用 Python 作为主要实现语言」，
   我们这条链不满足；如果只是允许使用，那没问题。**请向主办方确认口径。**
2. **CI/CD 是否必须**：本项目有自动化测试（`npm run test:unit`）与打包脚本，
   但**没有**配置云端 CI（GitHub Actions 等）。如果「CI/CD」是硬性要求，我们需要补。

这两条我没有写成「旧要求已取消」，也没有自行按「不需要」处理。
