# 数据存储、升级与备份（v0.5.0）

本文只写**已经实现并在本机验证过**的行为。没有验证的会明确标注「未验证」。

---

## 一、记录存在哪里

| 项目 | 值 |
| --- | --- |
| 文件 | `history.db`（标准 SQLite 3 文件） |
| 目录 | `%APPDATA%\ai-conversation-copilot\`（即 `app.getPath('userData')`） |
| 本机实测路径 | `C:\Users\<用户名>\AppData\Roaming\ai-conversation-copilot\history.db` |
| 同目录还有 | `settings.json`（设置，Key 用 Windows DPAPI 加密）、`logs/app.log`（运行日志） |
| 不在哪里 | 不在安装目录（`Program Files`）、不在临时目录、不在发布目录 |

界面里能看到真实路径：**记录面板底部**「记录保存在本机（…）」，或设置 → 通用 → 记录。

## 二、存了什么

一张 `sessions` 表 + 一张 `messages` 表 + 一张 `facts` 表（关键信息卡）。

- `sessions`：会话 ID、标题（自动取第一句对方原文，可改）、语言、场景、
  音源用途、创建时间、更新时间。
- `messages`：消息 ID、所属会话、`seq`（稳定顺序号，分页游标用它）、时间戳、
  说话角色（对方 / 你）、音源通道（系统声音 / 麦克风）、外语原文、中文译文、
  中文谐音、IPA、音节切分、用户输入的中文、已展示的 AI 回复、状态
  （final / partial / pending / failed / cancelled）、置信度、失败原因、
  是否被用户改过、纠正说明。
- `facts`：这条字幕上抽出的时间 / 日期 / 金额 / 数量 / 人名 / 机构 / 事项，
  以及是否被用户确认或修改。

**不存**：原始录音、屏幕截图、视频、API Key 明文（Key 在 `settings.json`，
由 Windows `safeStorage` 加密；系统不支持加密时只在内存里、重启要重填）。

## 三、什么时候写

| 时机 | 行为 |
| --- | --- |
| 会话开始 | 生成 `s-<时间戳 base36>-<随机>` 作为稳定 ID，先建行 |
| 一句话定稿 | 立刻写入（**不等退出**），拿到回执后界面才显示「已保存」 |
| 译文 / 谐音 / AI 回复到达 | 用**同一个消息 ID** 更新同一行，不产生重复记录 |
| 连续改动 | 300ms 合并（含半句时 900ms），避免每帧写盘 |
| 写入失败 | 指数退避重试（1s → 30s 封顶），界面标「保存失败 · 重试保存」 |
| 关窗 / 退出 | `closeHistoryStore()` 只收句柄，**不依赖它保存数据** |
| 异常退出（断电 / 被杀） | 已 COMMIT 的数据仍在；靠 SQLite 的回滚日志保证原子性 |

> 关于 WAL：本机实测这个 WASM 构建下 `PRAGMA journal_mode=WAL` 不生效，
> 会退回 `delete` 回滚日志模式。回滚日志同样是原子的（提交即落盘、崩溃时回滚），
> 所以这里**不宣称使用 WAL**。

## 四、加载方式（界面不会一次全读）

- 打开一段记录：一次读最后 **50 条**（`getPage({limit: 50})`）。
- 往上翻：点「加载更早」，按 `seq` 游标再取 50 条，拼在最前面；
  顺序固定、不重复、不遗漏（游标用 `seq` 不用时间戳 —— 同一毫秒可能有多条）。
- 会话列表：一次 30 段，底部「加载更多（更早的会话）」。
- 搜索：搜标题 / 原文 / 译文 / 谐音，返回命中会话 + 摘要片段。
- 详情区用 `content-visibility: auto`：屏幕外的消息不参与布局与绘制
  （等价于虚拟列表），同时保留 DOM，读屏仍可访问。

**界面只加载一页 ≠ 其他内容不存在。** 数据库里没有条数上限，也没有
「超过 N 条自动删最旧」的逻辑。

## 五、升级 / 重装 / 卸载

| 动作 | 记录会怎样 |
| --- | --- |
| 覆盖安装新版本 | `history.db` 不动，直接沿用；表结构升级用 `PRAGMA user_version` 迁移 |
| 迁移重复执行 | 幂等（本机测试：连续 `open()` 两次，会话数与消息数不变） |
| 卸载软件 | 安装目录被删，`%APPDATA%\ai-conversation-copilot` 通常保留 |
| 重新安装 | 只要 `%APPDATA%` 目录还在，记录就还在 |
| 换电脑 | **不会自动同步**，需要自己「导出全部」或「备份数据库」再拷贝 |

迁移失败时会保留旧库、不删数据，界面提示「记录升级没完成」并提供
「打开记录文件夹」让你先备份。

## 六、导出与备份

| 功能 | 做了什么 | 适合什么时候用 |
| --- | --- | --- |
| 导出全部（文本） | 每段会话一段，逐条写「时间 / 角色 / 原文 / 译文 / 谐音」，20 段一批追加写，长会话不卡界面 | 要交作业、要发给别人看 |
| 导出全部（JSON） | 结构化：sessions + messages + facts，含全部字段 | 要迁移到别的工具 |
| 导出这一段 | 单会话文本 | 只交某一次对话 |
| 备份数据库 | `VACUUM INTO` 生成一致性快照 | 升级前、清空前、定期备份 |

**为什么备份不用「复制文件」**：数据库在写的时候文件内容不是自洽的，
直接 copy 可能拿到半个事务。`VACUUM INTO` 会让 SQLite 自己导出完整一致的副本，
本机测试验证过备份文件可以独立打开、条数与完整性 `ok` 都对得上。

## 七、出错时会怎样（不会假装成功）

| 情况 | 界面表现 | 数据影响 |
| --- | --- | --- |
| 目录不可写 / 权限被锁 | 「记录目录不可写」+ 下一步 | 不写，不删旧数据 |
| 磁盘满 | 「磁盘空间不足，记录没能保存」 | 不写，不删旧数据 |
| 库文件被另一个进程占用 | 「记录文件被占用」 | 重试即可 |
| 库文件损坏 | 「记录记录文件损坏」+ 先导出 | 不自动删库 |
| 数据库打不开 | 记录面板显示「记录功能现在不可用」，**字幕与翻译照常工作** | 不影响主功能 |

**任何情况下都不会自动删除最旧的记录**来腾空间。

## 八、删除操作是三件不同的事

| 操作 | 位置 | 影响 |
| --- | --- | --- |
| 清空当前字幕 | 字幕区右上角「清空」 | 只清屏幕显示，**记录不受影响** |
| 删除一段记录 | 记录面板 → 那一条 → 删除（二次确认） | 删这一段和它的消息、事实卡 |
| 清空全部记录 | 记录面板底部 → 清空全部（二次确认） | 删所有会话，不可恢复 |

## 九、隐私边界（实话）

- 本地保存**不等于加密**：能登录这台电脑的人可以直接读到 `history.db`。
- 没有云账号、没有自动上传；导出与备份都由用户主动发起。
- 日志（`logs/app.log`）只记状态、错误码、字数、耗时，不写原文 / 译文 / 谐音。
- 卸载重装不会把记录带走，也不会把记录还给别人 —— 它就在你这台机器的
  `%APPDATA%` 里。
