# 本地镜像 AWS 验证（2026-11-10）

目标：在**不碰真 AWS 账号、不花钱**的前提下，把「上线要用的那套 AWS 动作」先在本地演练一遍，
让以后迁真 AWS 时命令和心智模型能直接复用。

## 结论先行

| 真 AWS 服务 | 用途 | 本地等价物 | 结果 |
|---|---|---|---|
| ECR（镜像仓库） | 存 Docker 镜像，部署时拉取 | 本地 Docker Registry（`localhost:5000`） | ✅ 已通 |
| EFS（持久文件系统） | 存反馈库，跨重启/跨部署不丢 | Docker 命名卷（`-v copilot-feedback:/app/data`） | ✅ 已通 |
| ECS Fargate（无服务器容器） | 跑应用容器 | 本地 `docker run` | ✅ 已通 |
| LocalStack（模拟整套 AWS API） | 用 AWS 命令本地演练 | — | ⚠️ 卡在 token 政策 |

**核心价值已达成**：ECR「推镜像」和 EFS「持久化」这两件最需要演练的事，本地都跑通了。
LocalStack 只是锦上添花（想用 AWS 原生命令本地练手），但被它的新政策卡住，见下。

## 一、本地 Docker Registry 模拟 ECR（✅ 已通）

真实 ECR 的推镜像命令是：

```bash
docker push 297939505526.dkr.ecr.ap-southeast-2.amazonaws.com/copilot-web:degraded
```

本地 Registry 模拟的是**同一套动作**，只是地址换成 localhost：

```bash
# 1. 启动本地镜像仓库（模拟 ECR 的 registry 端点）
docker run -d --name local-ecr -p 5000:5000 registry:2

# 2. 给本地镜像打上「仓库地址 + 标签」，等价于 ECR 的 repository:tag
docker tag copilot-web-degraded:latest localhost:5000/copilot-web:degraded

# 3. 推送，等价于真实 ECR push
docker push localhost:5000/copilot-web:degraded

# 4. 验证仓库里确实有它
curl http://127.0.0.1:5000/v2/copilot-web/tags/list
# → {"name":"copilot-web","tags":["degraded"]}
```

**实测结果**：push 成功，digest `sha256:0373ea…`，仓库 tags 列表可见。以后上真 AWS 时，
只要把 `localhost:5000` 换成 `297939505526.dkr.ecr.ap-southeast-2.amazonaws.com`（已在你账号里建过 ECR），
命令一字不改。

## 二、Docker 命名卷模拟 EFS 持久化（✅ 已通）

EFS 在真 AWS 上的作用：容器重启、重新部署后，`/app/data` 里的反馈库**不丢**。
本地用命名卷做的正是同一件事，上一轮 CD 验证已实测闭环：

```bash
docker run -d --name copilot-verify -p 8000:8000 \
  -e COPILOT_DATA_DIR=/app/data \
  -v copilot-feedback-verify:/app/data \
  copilot-web:verify

# 写一条反馈 → 得到编号 FB-20261110-814FFF
# docker restart copilot-verify
# 查 FB-20261110-814FFF → 仍在 ✅
```

真 AWS 上等价物：ECS task definition 里给容器挂一个 EFS 卷（terraform 的 `efs.tf` 已写好这套），
`/app/data` 指向 EFS 挂载点，跨部署数据不丢。

## 三、LocalStack（⚠️ 卡在 token 政策）

原本想用 LocalStack 社区版在本地跑一套「S3/ECS/EFS 的 AWS 原生命令」，但实测卡住：

- **ECS/EFS/ECR 本身是 LocalStack Pro（付费）功能**，社区免费版不支持。
- **2025 年后 LocalStack 连社区版也强制要求账号**：启动即报
  `License activation failed … set LOCALSTACK_AUTH_TOKEN`，`ACTIVATE_PRO=0` 也无法绕过。

结论：LocalStack 现在需要**注册 LocalStack 免费账号、拿 auth token** 才能用，已不是「零注册零成本」。
本项目当前不需要它——Registry + 命名卷已经覆盖了要演练的核心动作。

## 四、与真 AWS 的差异（诚实边界）

本地验证证明了「流程走得通」，但**不等于真 AWS 一定能成**，差异点：

1. **网络**：本地是 localhost，真 AWS 是跨 VPC/安全组/ALB，涉及安全组放行、路由、域名 HTTPS 证书。
2. **IAM 权限**：本地无需鉴权；真 AWS 推 ECR、挂 EFS 都要 IAM 角色策略（terraform 的 `iam` 部分已写，未实测）。
3. **计费**：本地零成本；真 AWS 的 ECS Fargate + EFS 约 $50–70/月。
4. **LocalStack 未参与**：S3/ECS/EFS 的原生命令演练未做（卡 token）。

## 五、什么时候上真 AWS

当你决定「值得花 ~$50/月、并愿意配域名 + HTTPS 证书」时，迁移路径已就绪：
1. terraform 模板（ECS Fargate + ALB + EFS + ECR + IAM）已写好，见 `terraform/`；
2. 本项目的 Docker 镜像已能本地构建（完整版含模型 2.89GB / 降级版 797MB）；
3. 推镜像命令、挂持久卷命令本地都已验证过结构。
