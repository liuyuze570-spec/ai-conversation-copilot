## 一、离线演示：不管理解语言选什么，译文都是「明天 / 下周」

### 现象

演示模式下输入 `Please send the report by 3 p.m. tomorrow.`：

- 理解语言 = 中文 → 显示「明天 / 下周」；
- 理解语言 = 日语 → 还是中文；
- 理解语言 = 英语（目标是日语）→ 原话是日语，一条都对不上。

### 原因（代码层）

`src/services/mock/mock-translation.ts` 只有一条「英→中」查表，查不到就把**命中的
关键词**用 ` / ` 拼起来当译文。`tomorrow` 命中 `WORD_HINTS` 里那条
`[/\btomorrow\b|\bnext week\b/i, '明天 / 下周']`，于是整句变成「明天 / 下周」。
`TranslateRequest.to`（理解语言）这个字段它**从头到尾没读过**。

### 改法

1. 三句样例各自带 **zh-en / ja-en / en-ja 三个版本**（原话 + 参考译文 + 该抓的重点 +
   哪条值被否定），都写在 `src/shared/samples.ts` 里；
2. 离线翻译先按 **`理解语言|原话`** 精确查表（`SAMPLE_TRANSLATIONS`）；
3. 目标是中文时再查内置语料表；**长句不再拼关键词**（≤3 个词才走关键词兜底）；
4. 非中文方向没有预置译文时，明说「演示模式没有这句的日语译文，不拿中文顶替」，
   并把原话原样留着 —— 编一句假译文比空着更糟；
5. 演示脚本也跟着方向走：理解语言不是中文时，自动播放 / 「说一句示例」播的就是
   这三句样例（`src/main/audio/mock-engine.ts`），每一句都有对应译文；
6. 样例面板按方向显示；当前组合没有预置样例时，面板直接说「这一组没有预置样例」。

### 验证

`node .dev/samples-unit.mjs` → **76 条断言**，其中：

- 三方向 × 三样例的译文**逐字等于**参考译文（9 条）；
- 同一句原文切理解语言得到不同语言（日语版有假名、且有日语助词）；
- 非中文方向未收录句子 → 提示里出现「没有这句的日语译文」「不拿中文顶替」；
- 演示回复的释义：日语理解 → 日语释义，英语理解 → 英文释义，中文理解 → 中文释义。

## 二、保存失败时 AI 回复会永久丢

### 现象（代码审计确认，不是你手动复现的）

`src/renderer/lib/history-sync.ts` 的 `runFlush()` 顺序是：

```
把回复塞进 known（已保存缓存） → 清空 pendingReplyText → 才发数据库
```

只要这一次 `historyUpsert` 失败：

- `known` 里已经是「带回复」的样子 → `collect()` 认为这行没变化，不再重发；
- `pendingReplyText` 已清空 → 重试时没有回复可补；
- 界面还写着「尚未保存」。

结果：回复永久丢失，重试也补不回来。

### 改法

1. 待写回复改成 `pendingReply = { id, text }`，**只在收到成功回执之后**才清；
2. 并回复这件事抽成纯函数 `attachPendingReply()`（`src/shared/history.ts`），
   返回 `{ rows, replySent }`：`replySent === false` 表示这一行还没进库，**不假装成功**，
   下次再补；
3. `known` 只在成功后更新，失败时保持旧值，下一轮 `collect()` 才能重新收进来；
4. 写入期间新到的内容不会被旧批次覆盖：每批都是发出去那一刻的快照，
   成功后才写入 `known`，内容变了下一轮自然再发。

### 顺手修的三个同源问题

| 问题 | 改法 |
| --- | --- |
| 对方的话一律记成「系统声音」 | 按实际采集通道：现场沟通模式（麦克风收对方）记 `mic` |
| 「没提供」和「用户清空」分不开 | `HistoryMessage.cleared` 白名单（translation/romanization/reply/correction/meaning/userInput），DB 在 upsert 之后补一条 `UPDATE ... SET x=''`；不声明清空的空值仍然不覆盖 |
| 历史分页/记录完整性 | 维持 `seq` 游标与 `LIMIT n+1`；本轮回归里 50→100 条仍通过 |

### 验证

- `.dev/samples-unit.mjs` S7（9 条）：命中本批 / 只存在于已保存 / 行还没进库 /
  不改原数组 / 重复回复取最新；
- `.dev/history-unit.mjs` K21–K24（4 条）：不声明清空 → 空值不覆盖；声明清空 →
  真的清掉；**重开库之后**两种语义都还成立。

> 边界说明：`pendingReply` 在内存里，如果程序被强杀（不是正常退出），这一条回复
> 确实会丢 —— 界面会停在「尚未保存」。这属于「进程被杀」的已知代价，没有解决。

## 三、「整个程序退掉再打开」：第一次真的测了

以前交付文档写的是「部分执行：只做了关库重开 + 窗口 reload」。这两件事都**不走**
真实退出流程（`will-quit` / `before-quit`），证明不了用户关掉软件再打开还在。

新增 `src/main/selftest-v061.ts` + `.dev/run-v061-restart.js`：

1. 起第一个进程（`COPILOT_V061=write`）：改三类字号（21/27/15）、改语言方向
   （日语理解 / 英语表达 / 片假名 / en-GB）、写 3 条记录（含回复与提示体系）、
   写 2 条事实（1 条已确认、1 条被否定），然后 `app.quit()`；
2. 起**第二个进程**（`COPILOT_V061=read`，同一个 `--user-data-dir`）：读回来逐项比对。

结果：**15 项一致 / 0 项不一致**（源码版与打包版各跑一遍，见第 5 节）。
比对项包括：三类字号、理解语言、提示体系、口音、记录条数、原文、译文、回复、
提示体系、seq 连续、事实「已确认」、事实「被否定」。

## 四、确认卡与读音辅助补的部分

| 需求 | 之前 | 现在 |
| --- | --- | --- |
| 被否定的旧值 | 只在值上加中文「不是」前缀（日语值会变成「不是火曜日」） | 结构化 `negated` 字段；值保持干净，界面按语言显示「被否定」 |
| 更正句里的新值 | 整句含「変更 / 改成」时，新值也被标成「已更正」 | 按值判断，只有被否定的值才 `corrected`；新值是 `stated`（待核对） |
| 生成确认句 | 只能走模型；演示模式（mock 不返回 JSON）直接失败 | 本地兜底：用勾选的**原话片段**拼句，数字一个都不会变；模型失败/超时/改数字也会退到这条 |
| 确认句内容 | 可能把已作废的周二也念进去 | 只念当前理解；被否定的旧值不进句子 |
| 修改/确认记录 | 只有 `edited` 标记 | `confirmedAt` + `log`（edited / confirmed / unconfirmed，含前后值） |
| 个人词表 | 没有 | 点词 → 「存为我的读法」，按提示体系分开存，来源标 `manual`（不算专家核对） |

个人词表的验证在 `samples-unit` S8（14 条）：覆盖而不是新增、两种体系互不顶掉、
非法输入被清洗、命中后 `origin = manual`、删掉后回到规则结果。

## 四·五、读音：把「查到的」和「猜的」分开

### 现象（打印真实输出才看见）

把 10 句常用表达的真实提示行打出来（`node .dev/reading-list.mjs`）之后，看到三处硬错：

| 原文 | 之前显示 | 问题 |
| --- | --- | --- |
| `PDF` | 普德夫 | 把三个字母当一个音节拼，念出来对方听不懂 |
| `QR` | 克尔 | 同上 |
| `p.m.` | 普姆 | 同上；正确是念字母 P、M |
| `Mr.` | 姆尔 | 称谓缩写该念 `米斯特` |
| `Okafor` / `Tanaka` | 奥卡福尔 / 塔纳卡，**和词典命中的词标成一样** | 猜的读法和查到的读法看起来没区别，等于把猜测冒充成已核对 |

### 改法

1. **缩写不再走「字母→汉字」的拼读**：全大写 2–5 字母按**字母名**逐个念（`PDF` → `匹 迪 艾夫`），
   带点缩写查表（`p.m.` → `皮艾姆`、`Mr.` → `米斯特`）；分词器把 `Mr.` 切成 `Mr` 也认。
2. **新增第三种状态 `approx`（规则近似）**：`ok` = 词表命中、`approx` = 规则拼出来的、
   `unknown` = 给不出。整句状态与每个片段都有，界面显示「规则近似 N 段」，不是只靠颜色区分。
3. **补会议/日程高频词进词表**：星期、月份、`meeting / budget / report / dollars / available /
   deadline / delivery …` 与短功能词（`by / from / at / to / in / on`）。这些词规则拼读错得最多，
   而它们几乎每个句子里都有。
4. **日语补 `送`**：`送ってください` 被切成「送 + って」，之前 `送` 没有读音整句变「部分未确定」。
5. **单个字母按字母名念 + 带点缩写先合回一段**：这条是**打包版自检**打出来的 ——
   修完缩写后，界面里 `p.m.` 还是「普 姆」。原因是 Chromium 的 ICU 把它切成 `p` + `m`
   两段（Node 的 ICU 切成一段），两次都落到规则拼读。现在合并「字母 + 点 + 字母」的片段
   再查表，自检输出从 `3 普 姆` 变成 `3 皮艾姆`。

### 验证

- `hint-unit` 68 → **78 条**：新增 I 组（PDF 念字母 / p.m. 不再读普姆 / Mr 读米斯特 /
  词典外姓名标 approx / 词典命中标 ok）、J 组（meeting、Thursday 走词表，整句 `ok`）；
  G 组断言改为「数字不把整句拖成 partial」，另钉数字自身为 `ok`。
- 10 句清单见《读音核对清单-v0.6.1.md》，里面每一行都是程序原样导出的输出，
  **核对栏全部留空 —— 没有任何母语者核对过。**

### 仍然不准的地方（主动写下）

- 片假名体系对英语句子全部是规则转写，程序自己标 `approx`。
- `30分` 的 `分` 仍显示「未确定」：真实读法是 `ぷん` 不是 `ふん`，单看一个字定不了，不猜。
- 汉字近音整体没有母语者核对，也没有测过「照着念对方能不能听懂」。
