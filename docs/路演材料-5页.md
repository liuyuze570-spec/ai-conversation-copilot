# 路演材料 · 5 页

> 每页对应一屏。斜体是讲述提示，不投在屏幕上。

---

## 第 1 页 · 问题

**听障使用者参加英语线上会议，声音不是一个可用的信息通道。**

- 通用字幕工具的字幕在别的窗口里，焦点在自己要操作的窗口上；
- 只有英文原文，读一半要靠猜；
- **最容易听错、也最不能错的**：时间、日期、金额、否定（"不是周二"）；
- 漏掉一句之后，没有任何补救动作 —— 只能等对方再说一遍。

*讲述：先说场景，不说技术。一句话点出"不是没字幕，是字幕不在能用的位置"。*

---

## 第 2 页 · 我们只做一件事

**把"对方刚说了什么"变成能读的中文，并且让读不懂时有事可做。**

- 系统声音 → 英文原文 + 中文译文（译文是主阅读对象：23px 起，最大 40px）
- 关键信息单独抽出来：时间 / 日期 / 金额 / 数量，纠正关系标成「不是 X」
- 三张**离线**沟通卡：请再说一遍 / 请慢一点 / 请把关键时间写下来
- 全部断网可用（沟通卡），不急不花额度

*讲述：强调"一个场景一个功能"。不要说成万能翻译器。*

---

## 第 3 页 · 无障碍不是加几条 ARIA

| 做的 | 怎么验证的 |
| --- | --- |
| 译文对比度 14.92:1，高对比 21.00:1 | 先把半透明合成到底色再算（旧的 `white/45` 只有 4.51:1） |
| 字号 18–40px 可调，40px 不裁切不遮按钮 | 脚本点 A+ 到上限，量像素与矩形 |
| 状态不只靠颜色，每档都有文字 + 下一步 | 六种音频状态逐条断言 |
| 自绘下拉可全键盘操作（↑↓/Enter/Esc/首字母） | 焦点全程留在触发器，`aria-activedescendant` 报位置 |
| 控件名称来自同一行的标签，不是统一「请选择」 | `aria-labelledby` 由 Row 生成 |
| 打开设置焦点移入、关闭还给入口、Tab 不出面板 | 焦点陷阱 + 归还 |

*讲述：这一页是全篇最值钱的一页 —— 无障碍在这个作品里是功能，不是补丁。*

---

## 第 4 页 · 它出错时会怎么说

**不写"失败了"，写"哪里卡住 + 下一步做什么"。**

| 用户看到 | 真实含义 |
| --- | --- |
| 采集中，暂未收到声音 | 采集在跑，最近 8 秒没有声音进来 |
| 音频采集失败 · 点「重新连接」 | 音频进程没起来，不需要重启软件 |
| 翻译失败 · 余额不足 | 保留原文，逐句可重试 |
| 这里有一段没转写 | 队列积压 / 识别超时，那句话没进来（不假装连续） |

一次 silent 事件不会让自动回复永久失效；引擎死了清掉配置指纹，点开始能真的重起。

*讲述：举一个真实踩到的坑 —— 一次静音事件让整场自动回复失效，用户以为软件坏了。*

---

## 第 5 页 · 边界与下一步

**已经做到的**：采音 → 识别 → 翻译 → 字幕全链路；525 条自动化断言；
三组样例的规则层全部通过；打包与进包字节核对完成。

**还差什么（如实说）**：
- 真实音频端到端**未执行**（缺可公开的英语语音 + 服务商额度）；
- 目标使用者体验**未执行**（需 1 名听障使用者实测并记录）；
- 需要联网 + 自己的 Key，**本机 Python 只负责采音，不是离线识别**；
- 不做说话人分离，两个人共用一支麦克风时角色会混。

**下一步**：回复改流式（当前平均 8 秒）→ 四六级听力切入 → 生词本。

*讲述：把"未执行"说清楚，比把"已通过"说满更容易被信任。*
