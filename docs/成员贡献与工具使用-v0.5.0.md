# 成员贡献与工具使用记录（v0.5.0）

> 原则：**谁负责什么就写谁**。用户负责需求、取舍、体验判断与验收；
> AI 助手（WorkBuddy / Claude 系模型）负责代码实现、测试脚本与文档初稿。
> 不把 AI 写的东西记成"成员贡献"，也不把用户没做的事记成已完成。

---

## 一、成员

| 角色 | 承担 |
| --- | --- |
| 项目负责人（个人参赛） | 产品定位、需求取舍、每轮验收、真机运行与反馈 |
| AI 编程助手（WorkBuddy） | 代码实现、回归测试、构建打包、文档初稿 |

## 二、本轮（0.5.0）分工明细

| 工作项 | 负责人 | 说明 |
| --- | --- | --- |
| 作品定位收窄到「听障使用者的英语沟通字幕助手」 | 用户 | 决定了"一个场景一个功能"，否掉了继续加语言/社区/生词本 |
| 明确「三类字号必须各自独立」 | 用户 | 用户先指出旧版"译文比原文小 2px"的绑定是错的 |
| 字号范围与默认值（12–64 / 18 / 24 / 18） | 用户定方向，AI 落数 | 用户要求"不能无提示缩回小字" |
| 记录必须持久化、能导出、能删除、不能假装成功 | 用户 | 用户给了逐条验收标准（保存时机、失败提示、分页、搜索） |
| 三组样例的句子与验收点 | 用户 | 句子与"不能编日期/必须保留否定"是用户给的原文 |
| 技术选型（SQLite / node-sqlite3-wasm / seq 游标） | AI | 先做可行性验证再落地，见下 |
| `reading.ts` 重写、三类字号贯通到字幕/历史/回复卡 | AI | 含旧设置迁移规则 |
| `history-db.ts` / `history-ipc.ts` / `history-sync.ts` / `RecordsPanel` | AI | 含事务、分页、导出、备份、错误说明 |
| 音频生命周期修复（音源进指纹 / 代次 / 只死一次） | AI | 用户提出"切换音源无效、旧回执覆盖新连接"的现象 |
| 无障碍收尾（弹层 inert、`aria-activedescendant`、设备下拉命名） | AI | 用户要求"卡片打开后背景不能被键盘操作" |
| 自检脚本 `COPILOT_V050` 与 `history-unit.mjs` | AI | 用户要求"要有真实界面证据，不要只写静态分析" |
| 真机运行、判断哪里"看起来像丢了" | 用户 | 「重开后一片黑」是用户视角发现的问题 |
| 隐私说明文案改成"记录会保存、本地不加密" | 用户定要求，AI 改写 | 用户明确"旧版关闭即消失必须改掉" |
| 文档（使用说明 / 存储备份 / 字号操作 / 无障碍走查 / 测试记录） | AI 初稿 | 数字由脚本产出，用户复核 |
| 最终取舍：不做云后端、不做 CI/CD、不宣称 AWS 部署 | 用户 | 明确"没有就是没有" |

## 三、AI 用了什么工具 / 做了什么验证（避免"看起来做了"）

| 动作 | 具体做法 |
| --- | --- |
| SQLite 可行性 | 先用纯 Node 验证 CRUD / 事务 / 中文 + emoji / `user_version` / `quick_check`；再在 Electron 33.2.1 主进程里跑一次临时应用，输出 `ELECTRON_SQLITE_OK` |
| 单测 | 8 个套件 661 条断言，全部 `import dist/`（跑的是进包的同一份代码） |
| 记录库测试 | `.dev/history-unit.mjs`：临时目录跑真 SQLite，100 会话 / 1 万条 |
| 界面自检 | `COPILOT_V050`：真实窗口点真按钮、读 `getComputedStyle`、读 IPC 回执，产出 `report.json` + 8 张截图 |
| 打包 | `npm run dist:win`（ASCII 暂存目录，绕开中文路径导致的 builder 崩溃），随后核对 asar 内容 |
