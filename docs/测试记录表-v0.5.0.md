## 二、记录库集成测试细节（实测-自动化）

真实模型的翻译质量**（演示模式下那句译文是关键词释义，形如 `明天 / 下周`）。

## 七、本轮修掉的问题（都有回归）

| 问题 | 根因 | 回归方式 |
| --- | --- | --- |
| 切换音源用途后不生效 | `pipelineSignature()` 不含 `sourceMode`，`shouldRestartPipeline` 认为配置没变 | 单测 K1 / K2 |
| 旧的启动回执覆盖新连接 | 缺启动代次；停止 / 重连后旧回执仍然生效 | `StartOutcome.cancelled` + 单测 K5；`audioEpochRef` |
| 引擎死亡上报两次 | 双通道各报一次，上层「全部死」提前成立 | `deadReported` / `deathReported`（流级 + 引擎级各一次） |
| `listenToSystemAudio` 覆盖状态 | 先写「连接中」再等结果，失败后被覆盖回 starting | 重写为统一处理回执 |
| 日志可能带服务商原文 | `describeError` 在无 status 时会带上 message 前 80 字；设置读写还用 `String(error)` | 全仓改用 `describeError` / `errorCode` |
| 隐私说明写「关掉就清空」 | 0.4.0 文案没随记录持久化更新 | 自检 `0b-privacy` 断言 |
| 重开软件像丢了记录 | 启动不自动载入，空状态没有任何提示 | 自检 `14-after-reload` |
| 历史详情字号是硬编码 12/13/11px | 详情组件没读设置，主字幕调到 40px 到这里又变小 | 自检 `13-records-panel.detailFonts` 断言 |
