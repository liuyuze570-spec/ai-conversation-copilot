# 路演材料（5 页，v0.5.0）

> 每页一句话主旨 + 3~5 条要点 + 现场要展示什么。
> 不要念稿：每页开口第一句就写在这里。

---

## 第 1 页 · 问题：声音对他们不是信息通道

**主旨句**：线上英语会议里，声音一直在播，但有一群人只能靠猜。

- 听障使用者参加英文会议 / 上网课，靠自动字幕勉强跟上；
- 自动字幕只给外语原文，**读到一半要靠猜**；
- 时间、金额、日期这些"必须准确"的信息，恰恰最容易被听错；
- 最要命的是：一句没看清，**没有任何补救动作**，只能等对方再说一遍。

**现场**：不放视频，直接说这一句 ——「如果现在这段会议是英文，你听不见，
你能做的只有读字幕，而字幕只有英文。」

---

## 第 2 页 · 我们只做一件事

**主旨句**：把"对方刚说了什么"变成**能读的中文**，并且让读不懂时有事可做。

- 抓**电脑正在播放的声音**（不是麦克风、不是摄像头），任何会议软件都吃得下；
- 一行外语原文 + 一行**更大的中文译文** + 一行**中文谐音**（照着念）；
- 时间 / 日期 / 金额 / 数量单独抽成「重点信息」卡，先核对再行动；
- 读不懂时，三张**离线沟通卡**（请再说一遍 / 请慢一点 / 请把关键时间写下来），
  不联网、不花额度，点开就能给对方看。

**现场**：点底部「更多 → 三组样例」，跑第一句
`Please send the report by 3 p.m. tomorrow.`
→ 字幕三行 + 重点信息卡出现「3 p.m.」「明天」。

---

## 第 3 页 · 门槛是两个真实的具体数字

**主旨句**：我们把"能不能用"压到两个可验证的小目标上 —— **看清**、**找回来**。

- **看清**：三类文字（原文 / 译文 / 谐音）字号**各自独立**，12–64px，
  采集中改立刻生效，放大后底栏自动精简、字幕不裁切；
- **找回来**：每一句字幕自动存进本机数据库，关掉、重启、升级都不丢；
  重开软件空状态直接给「上次的记录还在 + 打开这段」；
- 出问题不写"失败了"，写"哪里卡住 + 下一步做什么"；保存失败会显示
  「尚未保存 / 保存失败」并给重试，**不假装成功**。

**现场**：把译文从 24 调到 40 → 指底栏自动精简；再打开记录面板 → 点开刚才那句。

## 第 4 页 · 我们怎么证明它不是 PPT

**主旨句**：661 条自动化断言 + 一次真实界面自检，报告和截图都在仓库里。

- `npm run test:all`：8 个套件 **661 条全通过**；
- 记录库真跑 SQLite：**100 个会话 / 1 万条消息**写入 2.4 秒，
  分页翻到底 100 条不重不漏，备份库能独立打开；
- 真实界面自检 17 步：点真按钮、读 `getComputedStyle`、读 IPC 回执，
  证据在 `docs/evidence-v0.5.0/`；
- 高对比是**真换底色**：读渲染色算出 **21:1**，不是纸上推导；
- **没做的照实写**：真实音频链路（账户余额不足，服务商返回 402）、
  真实模型翻译质量、目标使用者体验 —— 这三项本轮**未执行**。

**现场**：打开 `docs/evidence-v0.5.0/` 的截图和 `report.json`，让评委自己翻。

---

## 第 5 页 · 下一步与局限

**主旨句**：这是一个能用的工具，不是完成品；缺口写清楚比包装重要。

- **下一步 1**：回复链路目前全非流式，平均 8 秒 —— 改流式让第一句先出来；
- **下一步 2**：从「翻译器」走向「接话教练」—— 解决"我该说什么"，
  四六级听力是最好的切入口；
- **局限（必须说）**：需要联网 + 自己的 API Key；音频发给所选服务商；
  本地记录**没有加密**；不支持说话人分离；谐音是近似，不是标准发音；
  安装包没有代码签名；
- **后端 / 云**：本版**没有**部署 AWS 或任何云端后端，记录只在本机；
  CI/CD 也**没有**落地，只有本地脚本。

**现场**：主动把限制讲完，再问评委"如果只保留一个功能，你会留哪个"。
