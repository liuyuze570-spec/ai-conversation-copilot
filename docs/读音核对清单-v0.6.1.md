# 读音核对清单（v0.6.1）

> 这份清单的用途只有一个：**请一位目标语言熟练的人，把这 10 句的读音逐条听/读一遍，告诉我们哪里不对。**
>
> 下面每一行「提示（程序实际显示）」都是 `node .dev/reading-list.mjs` 在 v0.6.1 上
> 跑出来的**原始输出**，不是手写的、也不是按印象整理的读音。表格里的「状态」是程序
> 自己的判断：`词表命中` = 从词表查到的；`规则近似` = 本地规则拼出来的（本来就不准）；
> `未确定` = 给不出读音，界面显示空白而不是编一个。
>
> **不要把这些汉字近音当成已核对的发音。** 到目前为止，没有任何母语者核对过它们，
> 我们也从没测过「照着提示念、对方能不能听懂」。

## 怎么用（给核对的人）

1. 打开软件，把理解语言设为中文、目标语言设为英语（第 11–13 句改成日语目标）。
2. 逐句看「提示」那一行，**出声念一次**，判断：母语者听到会不会理解成这个词。
3. 在最后一列填：`对` / `不对，应读作 ___` / `不确定`。
4. 不对的词，直接在软件里点那个词 → 填自己的读法 → 保存（会存进「我的读法」，
   只对这一种提示体系生效，界面上标成人工、不标专家核对）。
5. 把结果发回来。我们会把确认为错的词补进词表或改规则，然后重跑这份清单。

记录表在最下面（第 14 节）。

## 这 10 句是怎么选的

覆盖这个软件真正会遇到的 5 类难点，每类至少 1 句：

| 类型 | 句子 | 为什么选它 |
| --- | --- | --- |
| 时间 + 缩写 | E01 `p.m.` | 0.6.0 把它读成「普姆」，是真实错读 |
| 改期（否定 + 星期） | E02 `from Tuesday to Thursday` | 主演示句；星期词规则拼读最容易错 |
| 金额 + 否定 | E03 `15,000 … not 50,000` | 主演示句；两个数字必须都能念对 |
| 姓名 + 称谓缩写 | E04 `Mr. Okafor` | 词典外姓名，必须标近似而不是冒充确定 |
| 小数金额 | E05 `$1,250.50` | 带小数点、千分位 |
| 首字母缩写 | E06 `PDF` / `QR` | 0.6.0 读成「普德夫」「克尔」，真实错读 |
| 电话号码 | E07 `+81 90-1234-5678` | 一整串数字，不该被拆错 |
| 日期 + 否定 | E08 `2026-11-12, not 2026-11-20` | 连字符日期不能被当减法 |
| 姓名 + 时间 | E09 `Ms. Tanaka … 5 p.m.` | 日语姓名 + 称谓 + 时间 |
| 否定 + 天数 | E10 `can't accept 30 days; … 45 days` | 否定词与两个数字同句 |

补充 3 句，用来验证「同一句换体系 / 换目标语言」不会串：

- **E02k**：E02 的同一句，提示体系换成片假名（给日语读者看）。
- **J01 / J02**：日语目标句（罗马字体系），含时间与否定改期。

## 已知缺口（先说清，别当成 bug 报回来）

1. **片假名体系对英语句**（E02k）全部是规则转写，程序自己标「规则近似」。
   它只保证「读音大致像」，不保证对外国人可懂。
2. **`分` 在 `30分` 里**（J02 第 11 段）现在是「未确定」。真实读法是 `さんじゅっぷん`
   （ぷん不是ふん），光看 `分` 一个字定不了，所以程序不猜、留空白。这是有意为之。
3. **人名一律标近似**（`Okafor`、`Tanaka`）。中文读者按汉字念外国人名，音准本来就靠猜；
   程序不假装知道。
4. 汉字近音**只是辅助**：软件同时提供慢速朗读与分句朗读，读的是目标语言原文，
   不是这行汉字。缺目标语言语音时界面会直说「缺少 en-US 语音」，不会拿中文声音顶替。
