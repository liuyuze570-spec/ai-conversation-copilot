# 2026-11-08（网页版 0.7.0-web.1）

## 做完的事

### 1. 本地翻译改成进程内 ONNX，去掉 Node 依赖
- 新增 `webapp/server/engine_mt_onnx.py`：onnxruntime + tokenizers 直接跑
  `Xenova/opus-mt-en-zh` 的量化 ONNX（encoder 52.9MB + decoder 60.2MB）。
- 引擎链默认变成 `local-onnx,provider,mock`；`local-opus`（Node 边车）保留为可选项。
- 实测比边车快：单句 615–876ms（边车 1900–2900ms），启动预热 load 845ms。
- 停掉 8100 边车后翻译照常，证明不依赖 Node。

### 2. 踩坑记录（下次别再试错）
- `tokenizer.json` 的 `normalizer` 是 `Precompiled` 且 `precompiled_charsmap=null`，
  Rust 版 `tokenizers` 加载会 **panic**；把 normalizer 置空再 `Tokenizer.from_str` 才行。
  导出时这张表就丢了，transformers.js 拿到的也是 null，所以两边行为一致。
- merged decoder 的 KV cache 走不通：`use_cache_branch=true` 返回
  `present.*.encoder.*` 形状是 `(0,8,1,64)`（退化），第三步 Reshape 崩。
  **解决办法：全程 `use_cache_branch=false`，每步喂整段 decoder 序列**
  （O(n²)，但 batch=4 beam 只要 0.8s，够用）。
- `past_key_values.*` 必须传，且 **encoder 侧长度要等于 enc_len**（内容不参与计算，
  只给图里的 Reshape 提供维度）；传 0 长度会报
  `ReshapeHelper: dimension with value zero exceeds`。
- `present.*` 输出喂回去要改名成 `past_key_values.*`。
- 想匹配边车输出必须做 beam search（模型 `num_beams=4`）；贪心会让
  `Hello.` 从「哈罗」变成「你好,我叫艾丽克丝」。

### 3. 识别质量
- `beam_size` 1→5 + `initial_prompt`：`3pm`→`3 p.m.`、`9am`→`9 a.m.`，代价 +100–200ms。
- **修不了**：`seven forty-five` → `745`，译文「745出发」有歧义。不猜着改
  （`room 745` 也会被改错），列为已知缺陷。
