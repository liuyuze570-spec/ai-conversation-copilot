## 0.3.6 · 稳定性 / 隐私 / 体验 系统加固（89 项单测）

用户给了一份基于 0.3.5 的静态审查清单（密钥、音频切句、回复乱序、超时异常、朗读、无障碍、性能），要求**直接修 + 验证**，不要只给建议。

### 一、密钥与接口（src/main/settings-store.ts、src/shared/key-binding.ts、src/shared/providers.ts、src/main/index.ts、src/main/preload.ts）
- **Key 与服务商绑定**：新增 `keyBindings{llm,stt}`，保存时记 host + providerId；发送前 `keyBelongsTo(binding, currentHost)` 不匹配 → `getApiKey()` 返回空（**旧 Key 绝不发给新服务商**）。老 Key 无绑定 → 按当时配置补绑。
- **公网强制 HTTPS**：`checkDomesticURL` 对非本地 http 返回 `insecure:true` 并拒绝；本地/内网仍放行且标 `local:true`。新增 `enforceHttps()`，迁移时**只升级 scheme、不换服务商**（换服务商等于把 Key 和模型一起废掉）。
- **加密不可用不再落明文**：`safeStorage` 不可用时 Key 只进 `sessionKeys`（内存），`ephemeralKeys` 标记；`persist()` 里做双保险：读到 `plain:` 先搬进内存**再**删字段。
  - 踩到自己的坑：`persist()` 一开始只 `delete`，而它比 `migrateKeyStorage()` 先跑 → 老用户明文 Key 被静默丢掉。**迁移顺序必须是 load → migrateKeyStorage → 其它**，且 persist 要先救再删。
- **不再向界面回传完整 Key**：`KEY_GET`/`KEY_PREVIEW` 只返回 `{present,masked,boundHost,currentHost,mismatch,ephemeral}`；preload 删掉 `getApiKey`，改成 `getApiKeyPreview`。
- **敏感 IPC 来源校验**：`isTrustedSender()` 要求主 frame 且 `copilot://` / `file://` /（非打包）`localhost:port`；`guarded()` 包住 settings/key/ai/system-check/doc/latency。

### 二、音频切句（src/shared/segment-vad.ts 新建、src/main/audio/python-engine.ts、status-heal.ts）
- 抽出纯状态机 `decideSegment()`。**旧实现的真 bug**：`enoughSpeech && (silenceMs>=vad || elapsedMs>=MAX)` 把两个上限和「语音块≥3」绑成「与」，于是 100–200ms 短噪声后 `speaking` 永远不释放，`segment` 每帧无条件追加静音 → **缓冲区无上限增长**（模拟 60 秒静音涨到 1.8MB）。
- 新规则三闸门独立：静音够久→够长收官/不够丢弃；时长上限独立生效；字节硬上限兜底。时长用「块数×100ms」算，不用墙钟。
- 缓冲区改 `Buffer[]` + `sum(commit)`，只在收官/中途快照时 `Buffer.concat`（旧的是每帧 O(n²) 复制）。
- **会话编号** `activeSessionId`：停止/重启时 +1，`emit()`/`status()` 对不上就丢 → 旧字幕不会混进新一场。`stop()` 会 abort 所有在途 STT（`AbortController` 一路传到 fetch）。
- **失败后恢复**：`healsAfterSuccess(lastStatus)` 把 `error`/`no-audio` 都捞回 `listening`（旧代码只看 `reportedNoAudio`，一次 STT 失败就让整场自动回复永久失效）。

### 三、回复乱序（src/renderer/hooks/useCopilot.ts）
- 每次请求 `replySeqRef +1`，**上下文与轮次在发起时快照**（旧的是回来时才读 `roundIndex`）；回来时 seq 对不上 → 成功/失败都丢弃。
- `busy` 改成**计数**（`repliesPendingRef`），并发时先完成那个不能提前关忙碌态。
- `closeReplies` / `stopListening` 会让 seq +1 → **迟到的回复不再把面板弹出来**。
- 朗读也有代次号：连点两张卡时，先结束的那句不能清掉后一句的播放标记。

### 四、HTTP 超时与异常（src/services/llm/http.ts 重写、reply-parse.ts 新建）
- `fetchWithRetry` → `requestText/requestJson`：**总预算**贯穿「重试 + 读响应体」（旧的在 `return response` 时清定时器，body 永远不来就永久挂住；且每次重试各自计时 45s×3）。
- 重试只对 408/409/425/429/5xx；**401/402/403 立刻返回**。`isDowngradableHttpError` 只允许 400/404/422 触发「换请求体再试」（旧的是 `4\d\d` 全都降级，Key 错也白打两次）。
- 模型 JSON 结构校验独立成 `parseReplyDrafts()`：`replies` 非数组、`chinese:123`（旧代码 `.trim()` 直接 TypeError 崩）、未知 `kind`、重复句、`syllables` 非数组全部收敛。
- STT/TTS 响应字段一律先判 `typeof`。

### 五、朗读（src/renderer/index.html、openai-tts.ts、web-speech.ts、ai-service.ts）
- **CSP 是真凶**：`default-src 'self'` 没有 `media-src`，云端朗读的 `data:audio/mp3` 直接被拒 → 点了没声音也不报错。补 `media-src 'self' data:`。

### 六、界面与无障碍
- `controls.tsx`：Toggle `role=switch/aria-checked`、Range `aria-valuetext`、Select `role=combobox/aria-expanded` + 菜单 `role=listbox` + 选项 `role=option/aria-selected`。

### 最终音频零字节的真因（已修，别再排查状态机返回值）
`decideSegment` 在 finish 时返回 `next: reset()`（bytes=0），旧 `handleFrame` 先
`segmentState = decision.next` 再 `Buffer.concat(chunks, segmentState.bytes)` ——
`Buffer.concat(list, 0)` 返回**零长度 Buffer**，`pcm.length >= MIN_FINAL_MS` 永不成立，
完整识别从未提交。修法：`main/audio/segment-buffer.ts` 的 `SegmentBuffer` 类把
「先 snapshot 再 reset」钉在类内部，`snapshot()` **不接受外部字节数参数**（那参数就是 bug 入口）。
不变量：`finish` 分支长度必须等于实际帧数（含触发收官那帧，不多不少）。

### 分段时长口径
`speechChunks + silenceChunks` 会漏算「说话→短停→又说话」里的短停。改用只增不减的
`state.totalChunks`，`segmentAudioMs(state, chunkMs) = totalChunks * chunkMs`。
**量化**：6 帧响 + 2 帧停的抖动长句，新口径第 120 帧（12s）收官；旧口径那一刻只报
9200ms，要跑到第 160 帧（16s）才到 12000ms —— 上限晚触发 4 秒。

### 密钥绑定用完整 origin + scheme 升级要跟随
- `bindingOriginOf()` → `scheme://host[:port]`（默认端口省略）；0.3.6 的 `{host}` 用
  `originOfBinding()` 补成 `https://host`。
- **0.3.6 的真漏洞**：明文 Key 搬进 `sessionKeys` 后 `delete this.data[field]`，随后
  `if (this.data[field] && !this.bindingOf(target))` 永远 false → 内存 Key 从未绑定；
  而当时 `keyBelongsTo(undefined,…)` 返回 true，端点自动切换后就发出去了。
- `unknown` 也**停止使用**（审计要求），迁移会补绑，正常用户落不到这档。
- **新发现的升级回归**：老配置 `http://api.siliconflow.cn/v1` 的 Key 绑到 http origin，
  紧接着 `migrateEndpoints()` 升级成 https → 严格比对判 mismatch，用户没换服务商却被停用。
  修法 `followSchemeUpgrade()`：只放行「同主机同端口的 http→https」，**反方向绝不跟随**
  （那是降级），并把绑定就地改写成 https。规则本身没放宽。
