# 2026-11-06 · 0.6.0（语言方向 + 读音辅助 + 双面卡）

## 做了什么

1. **语言方向四元组**：`uiLanguage` / `nativeLanguage` / `targetLanguage` / `hintSystem`(hanzi|katakana|romaji|none) / `accent`，`shared/languages.ts` 是唯一真相。只标三个方向「实测清单内」，其余标 structured。
2. **读音引擎重写**（`services/pronunciation-ja.ts` + `pronunciation-katakana.ts`）：修掉 `カメラ→kara`、`カタカナ→kaka`、`ガッコウ→gako`、`コーヒー→kohi`、`空港→空港`。关键：先整串 `toHiraganaText`、连续假名攒段再音节解析、词典对**每个位置**做最长匹配、促音双子音、长音复元音、助词 `は/へ/を` 只在**单独成段**时读 wa/e/o。
3. **`buildHintPlan`**：逐词片段 + 原文范围 ID（`"0-6"`）+ `HINT_VERSION=2`，`hintLooksWrong()` 用二元组重合率 < 0.25 拦无关读音。
4. **UI**：点词看读音（`data-word-seg` / `data-hint-seg` 联动）、双面卡 `ShowCard`（`data-show-*`）、语言方向设置面板（`data-native-select` / `data-hint-select` / `data-direction-status` / `data-voice-status`）、`data-speak-phrases`、`data-reply-show`。
5. **SQLite schema v2**：加 `comprehension` / `hint_system` / `hint_version` / `meaning`，`ALTER TABLE` + `table_info` 幂等；`ON CONFLICT` 里空值不覆盖已保存的 reply/meaning/hint_system。
6. **修 0.5.0 遗留 bug**：`toConversationItems` 漏了 `seq` → 「加载更早」永远算不出游标（>50 条翻不回去）。`startNewHistorySession` 改为返回 boolean，写失败不切会话；删除/清空走 `discardHistorySession()` 不 flush（否则刚删的内容被写回新会话）。

## 两个容易再犯的坑（记下来）

- **`DEFAULT_SETTINGS` 不能给「迁移闸门」字段默认值**：`readingVersion: 2` 会让 deepMerge 把没有该字段的旧设置补成 2，迁移永远不执行。同理 `hintSystem: 'hanzi'` 会让日语用户升级后仍看到汉字近音 —— 解法是 `settings-store` 记 `provided`（文件里真写过的 key），`!provided.has(x)` 才算没设置。
- **`executeJavaScript` 模板串里不能出现反引号**（这次在注释里写了 `` `shell.inert === true` ``，TS1005）。另外自检断言要在**状态还在的时候**取值：`shell.inert === true` 写在返回对象字面量里，等于在 Esc 关闭后才求值 → 恒为 false。
